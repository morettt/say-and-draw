
【先看这里：这个项目到底是什么】

这个项目是在做一个“会聊天、也会画数字和英文字母”的模型。用户输入“画一个数字3”或“画一个字母E”，模型不会直接输出图片，而是输出一串代表笔画的编号；后端再把编号还原成笔画坐标，网页最后把坐标画出来。

项目里有两套模型，职责不同：

1. 小型 Transformer：只负责根据数字或字母生成16个笔画编号。它不能正常聊天，但它生成笔画编号最稳定，是目前画图效果最好的基准模型。
2. Qwen3.5-0.8B：负责理解自然语言。它要判断用户是在聊天、要画什么，以及多轮对话里当前要画的目标。判断要画之后，它再生成笔画编号。

所以完整过程可以理解成：

用户说话 → Qwen理解意思 → 选择数字/字母和画图模式 → 生成16个编号 → VQ解码 → 笔画坐标 → 网页显示。

这份文档的目的，是让一个完全不了解项目的新 Agent 先明白项目，再按步骤复现。不要一开始就改代码或训练。先读完本段，再看“服务器和文件位置”，最后按“推荐复现顺序”执行。

复现时必须分清：Transformer实验和Qwen实验不是同一个模型，也不是同一套训练目标。Transformer主要验证“编号能不能生成好”；Qwen主要验证“能不能听懂用户并正确决定画什么”。

先记住最重要的关系
--------------------------------
原始数据是手写坐标。模型最终不直接输出坐标，而是输出16个编号；VQ码本和结构化解码器再把编号变成坐标和笔画。

完整流程：
手写坐标 → VQ编码 → 16个编号 → 生成模型预测编号 → VQ解码 → 结构化解码器 → x、y坐标 → 网页画线

不要把下面两套实验混在一起：
- 小 Transformer 只负责生成16个编号。
- Qwen 还要学习什么时候聊天、什么时候输出<DRAW>，然后再输出16个编号。

三、VQ和结构化解码器
--------------------------------
这两部分先训练好，之后两个生成模型共用它们。

VQ的作用：把一条手写坐标压缩成16个离散编号。

VQ模型：AlignedVQ
- 码本最多256个编号
- 每个编号对应32维向量
- 实际数字字母数据主要使用其中32个编号
- 每条字最多16个编号

结构化解码器：StructuredStrokeDecoder
- 输入16个编号对应的向量
- 输出最多8笔
- 每笔32个x、y坐标
- 另外预测实际有几笔

最终网页看到的就是这些坐标点连成的线。

四、复现小 Transformer
--------------------------------
小 Transformer 的模型结构：
- 4层
- hidden size 128
- 4个注意力头
- feed-forward size 512
- 词表大小69
- 实际输出32个有效VQ编号
- 参数量约81万

输入格式：
[BOS, 字符编号, 前面的编号……]

目标：
后面的16个编号。

起始训练脚本：
/root/autodl-tmp/retrain_codex_20261015/train_causal_vq.py

起始训练参数：
- seed=801
- batch size=64
- AdamW
- learning rate=2e-4
- 训练3000步
- 每个数字和字母按原脚本划分验证数据
- 字母以及数字4、5使用2.5倍采样

起点训练得到 causal_vq_generator.pt。之后用同一份权重继续训练生成器。

续训脚本参考：
/tmp/pen_fix/train_generator.py

续训参数：
- 从 step 500 权重开始
- seed=221
- batch size=64
- 初始学习率5e-5
- step 1200后降到1e-5
- 训练到2400步
- 保存800、1600、2400步
- 字母以及数字4、5使用2.5倍采样

最终选中的文件：
/root/autodl-tmp/retrain_codex_20261015/control_gen_1600.pt

选择原因：在6个候选权重中，自由生成笔迹匹配分最高，不是验证loss最低。

小 Transformer 已复现的结果：
- 总体笔迹F1：94.96
- 数字：90.78
- 字母：96.58
- 432条自由生成样本

这个F1是笔迹相似度，不是识字准确率。

七、Qwen聊天和绘画训练
--------------------------------
目标：让Qwen自己决定聊天还是画图。

普通聊天：
用户：你好
目标：你好！有什么想聊的？

绘画：
用户：请帮我写一个A
目标：好的，我给你写一个A。<DRAW>16个编号<END_DRAW>

禁止绘画：
用户：不要画，只告诉我A是什么
目标：只回复文字，不生成<DRAW>。

训练过程：
1. qwen_chat_letters_20261016：增加普通聊天、数字字母知识、不要画等数据。
2. qwen_multiturn_20261016：增加历史对话中的切换、纠错、停止绘画。
3. qwen_confirmation_20261016：增加“先询问能不能画，再说那你画吧”的完整多轮场景。

当前部署的模型是：
/root/autodl-tmp/qwen_confirmation_20261016/best/

确认对话版最终测试：
- 112次绘画请求全部触发绘画并对应到目标
- 平均目标笔迹F1：96.89
- 83次聊天请求中77次没有误画

八、Qwen推理流程
--------------------------------
用户输入完整对话。

模型读取：
- 系统提示
- 最近的对话历史
- 当前用户问题

模型自己生成文字。只有生成<DRAW>后，程序才允许后面生成16个<Mxxx>编号。

编号生成完后：
- 送入aligned_vq_smooth.pt
- 再送入structured_decoder.pt
- 得到笔画坐标
- 网页显示坐标线条

十、以后做动物和局部修改
--------------------------------
动物不能只靠当前数字字母数据生成，需要动物坐标数据。

修改训练可以沿用同一方法：

原始坐标：E
指令：删除E的上半部分
目标坐标：删除上半部分后的E

然后把目标坐标重新编码成16个编号，训练：
当前编号 + 修改指令 → 修改后的16个编号

模型仍然自己理解修改指令，输出修改后的编号。不要设计成让模型输出“删除第几笔”的命令。

修改训练必须加入保持数据：没有要求修改的部分尽量保持原样。

十一、复现时最容易犯的错误
--------------------------------
1. 不要把旧的385条纯数字数据和799条数字字母数据混用。
2. 不要改变字符顺序0123456789NBACDEFGHIJKLMOPQRSTUVWXYZ。
3. 不要把“笔迹F1”叫成识字准确率。
4. Qwen绘画推理必须让模型先生成<DRAW>，不能网页提前强制塞<DRAW>，否则无法测试它是否会聊天。
5. Qwen普通聊天和绘画数据必须混合训练。
6. 多轮测试要把完整历史传回模型，尤其要测试“先询问，再确认绘画”。
7. 新Agent如果要改训练参数，必须说明只改变了哪一个变量。
8. 6006部署前先做本地或远程接口测试，再让用户测试。
