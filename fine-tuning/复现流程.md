# 小型 Transformer 数字和字母模型：开源复现说明
 
目标：输入一个数字或大写字母，生成 16 个 VQ 编号，再还原成笔画并显示。

## 模型分工

- AlignedVQ：把原始 XY 坐标压缩成 16 个编号。
- Causal Transformer：学习“字符 → 16 个编号”。
- StructuredStrokeDecoder：把 16 个编号对应的向量转换成笔画数量和 XY 坐标。

流程：

```text
原始 XY 数据 → VQ 编号 → Transformer → 16 个编号 → 结构化笔画 → 画布
```

## 整体理解


#### 1. 小型transformer模型

首先。我们先从简单的开始。用一个自回归transformer模型。我这里用的是： Causal Transformer 这个是实际测试后发现笔迹质量最高的基准模型。
以及负责编码的VQ VAE模型：AlignedVQ

接下来的开发都会围绕这两个模型来。

我们需要实现的目标：输入数字0~9 \26个英文字母  给这个模型。模型输出给我们对应的数据，我们可以用模型生成的数据通过代码处理。转换映射在画布上面。画布显示对应的数字、字母。

实现流程：

1. 将真实的 26 个字母和 0~9 数字，用鼠标在特制 HTML 网页上一一绘制并记录数据。每个字符至少 15 条。

2. 将收集好的字母、数字数据训练 VQ VAE，让它学会把复杂的 XY 坐标压缩成 16 个离散编号。

3. 在第一次 VQ VAE 训练完成后，继续训练平滑版 VQ VAE。让数字、字母的线条更平滑，减少线条抖动。后续全部使用这份平滑版 VQ VAE。

4. 用平滑版 VQ VAE 生成的 16 个向量，加上原始手写数据中的真实分笔 XY 坐标，训练结构化解码器。

5. 用训练好的平滑版 VQ VAE 编码器，把所有原始训练数据压缩成 16 个离散编号。

6. 用这些编号训练 Causal Transformer，让 Transformer 学会根据输入的数字或字母生成 16 个编号。

7. Transformer第一版模型训练完成后，再进行一次续训。加载第一版Transformer模型，使用更小的学习率继续训练，这一步是为了提高编号生成和最终笔迹质量。

8. 将 Transformer 生成的 16 个编号，通过平滑版 VQ VAE 的码本查找对应的 16 个向量。

9. 将这 16 个向量交给结构化解码器，预测：
1. 这个字符实际有几笔
2. 每一笔的 XY 坐标
3. 每一笔从哪里开始、到哪里结束
4. 笔画之间什么时候抬笔、什么时候落笔

10. 将结构化解码器输出的 XY 坐标映射到网页画布上。

## Qwen3.5 训练流程

Qwen 第一、二阶段读取 `data/qwen/handwriting_stage1.jsonl`，第三至第五阶段的笔迹样本读取 `data/qwen/handwriting_draw.jsonl`。每行直接保存中文指令、目标回复、字符、16 个编号和训练/验证划分。五个阶段依次加载前一阶段的权重。

把 `aligned_vq_smooth.pt` 和 `structured_decoder.pt` 放到 `models/codecs/`。第一阶段训练脚本会检查 `models/qwen3.5-0.8b/`，基础模型缺失或不完整时自动通过 ModelScope 下载。

原始轨迹保存为 `data/digits_all.jsonl`。重新训练 VQ 或修改原始轨迹后，运行 `python -m data_tools.export_qwen --force` 更新笔迹训练 JSONL。

以下命令在本目录执行。
### 1. 笔迹训练

```bash
python train_qwen35_handwriting_stage1_repro.py
```

训练 35 轮。目标是：文字绘画指令 → `<DRAW>` + 16 个 `<Mxxx>` 编号 + `<END_DRAW>`。

每次单独运行都会在 `runs/qwen_stage1_oldmethod_restart/` 下创建独立的 `run_日期_时间_随机后缀/` 目录，启动时打印实际保存位置，不覆盖之前的权重。
也可添加 `--output-dir runs/我的训练名称` 指定目录；目录已存在时会直接报错。
完整训练结束后才更新 `latest.json`。第二阶段、一键流水线和评估脚本会自动读取最近完成的模型；旧版直接保存在原目录的权重仍可读取。

### 2. FP32 主权重续训

```bash
python train_precision_ablation_oldmethod.py fp32_master
```

从第一阶段模型继续训练 10 轮。前向计算使用 BF16，主权重和 AdamW 状态使用 FP32。

### 3. 聊天与绘画混合训练

```bash
python train_chat_letters.py
```

从 FP32 续训模型继续训练 12 轮，同时加入普通聊天、禁止绘画、数字字母知识和绘画样本。

### 4. 多轮对话训练

```bash
python train_multiturn.py
```

从第三阶段最佳模型继续训练 6 轮，加入历史对话中的目标切换、纠错和停止绘画。

### 5. 确认对话训练

```bash
python train_confirmation.py
```

从第四阶段最佳模型继续训练 3 轮，训练“先询问、用户确认后再绘画”的多轮场景。

### 6. 通用单轮与多轮对话训练

```bash
python train_general_chat.py
```

从 `runs/qwen_confirmation/best` 继续训练 3 轮，使用 `data/qwen/chat_stage6.jsonl`，并混入笔迹样本减少遗忘。每次保存到独立的 `runs/qwen_general_chat/run_*` 目录，不覆盖旧权重；按验证集对话 loss 加 0.2 倍笔迹 loss 选择最佳权重。训练完成后，网页自动加载最新完成的第六阶段权重。

原始 `通用数据集.txt` 中，空行前后视为不同对话，同一组连续问答保留历史。修改原始文件后运行 `python -m data_tools.general_chat` 重新生成 JSONL；训练集和验证集按整组对话划分。数据保留原文，未做事实纠错。超长样本会记录在本次 `experiment.json` 的 `skipped_long_turns` 中，可通过 `--max-length` 调整长度上限（默认 1024）。


### 独立评估一个模型

评估未微调的基础模型（需先下载模型）：

```powershell
python eval/evaluate_dialogue_regression.py --model models/qwen3.5-0.8b --label base_qwen35 --output eval/dialogue_runs/base_qwen35.json
```

之后可单独评估微调后的模型：

```powershell
python eval/evaluate_dialogue_regression.py --model runs/qwen_confirmation/best --label stage5 --output eval/dialogue_runs/stage5.json
```

每次只加载 `--model` 指定的一份模型。原 `--baseline`、`--candidate` 参数已由 `--model` 替代。
默认使用 20 条测试用例，可用 `--cases 自定义.jsonl` 指定其他用例。
用例每行必须包含唯一的字符串 `id` 和非空 `messages`，消息包含 `role` 和字符串 `content`。

裁判按理解、正确性、指令遵循、表达自然度四项分别给 1–5 分，脚本取四项均值作为该题得分。
报告保存逐题回答、各项分数和理由，以及总平均分、各项平均分，不再输出双方胜负。
同时记录评分标准版本、裁判提示词、用例哈希及生成参数，便于核对不同报告的评估条件。
比较训练前后的报告时，应使用相同的用例、裁判模型、评分标准和 `--max-new-tokens`（默认 160）；
LLM 评分存在波动，小幅分差应结合逐题回答和评语判断。旧版双模型报告与新版分数不宜直接比较。

Qwen 的普通聊天数据单独放在 `data/qwen/`：

```text
chat_stage3.jsonl          # 普通聊天、问答、禁止绘画
chat_stage4.jsonl          # 多轮上下文、改目标、停止和纠错
chat_stage5.jsonl          # 确认、拒绝、部分执行和重新确认
```

每行包含 `user`、`assistant`，多轮样本还包含 `history`。修改或扩充聊天数据时直接编辑这些 JSONL，不需要改训练脚本。

### Qwen网页推理

完成五个训练阶段后，使用 `best_qwen_chat_runtime.py` 处理 `<DRAW>` 和 16 个 `<Mxxx>` 编号，再用 VQ 和结构化解码器还原笔迹。网页文件是 `qwen_chat_page.html`，服务入口是 `live_server_qwen_final.py`：

```bash
python live_server_qwen_final.py
```

默认端口为 6006。网页输入普通问候时应只回复文字；明确要求写数字或大写字母时才生成笔迹。
